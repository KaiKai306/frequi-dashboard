# 策略、信号周期与仓位的统一比较

本轮把三种信号周期4h/1h/15m、七套固定规则、单笔100/250/450USDT、三段行情和两种成本全部组合，378项正式Freqtrade2026.10回测。现货BTC/ETH、初始1000USDT、最多两仓，统一5m细分撮合；不调参、不杠杆、不摊平、不接股票，不改正在运行的模拟账户。

规则及筛选口径先冻结于[PROTOCOL.md](PROTOCOL.md)，公开来源、实际读到的社区讨论及复现边界见[SOURCES.md](SOURCES.md)。权限和资源工程修正记录在工作目录的frozen*.json，未更改交易规则或参数。完整导出发现期末强平边界异常，统一补充终端价格并重跑全部2026组合126项；原始数据和结果留存，详见[TERMINAL-CORRECTION.md](TERMINAL-CORRECTION.md)。

- `prepare_data.py`：验证236份新增官方5m/15m归档，对齐时间精度、缺口和OHLC，并与首轮已校验1h行情核对。
- `strategies/StudyStrategies.py`：21个显式规则/周期变体；保持时间跨度的均线单列对照。3种投入通过配置重跑，非收益倍乘。
- `run_matrix.py`：固定镜像摘要、无网络、只读根目录、无端口及生产挂载；矩阵任务1GiB/1.5CPU，最多3个并行。先实测资源，和偏差检查合计最多4个研究任务。
- `offline_freqtrade.py`：仅用无凭据公共快照替代市场发现，其余引擎保持正式版本。
- `check_causality.py`：21变体×两币×五个截断，共210次前缀一致性检查。
- 框架`lookahead-analysis`：每变体抽查10信号，CSV/日志在工作目录。
- `export_reports.py`：逐笔核对PnL/费用及最终钱包，按共同5m标价独立重建含持仓净值、回撤、月度、暴露、年化及换手；每个周期/投入一份报告，成交和K线分文件压缩、按需加载，浏览器本地解压；无需修改代理配置。

运行研究：`python3 research/strategy-study/run_matrix.py --work <工作目录> --workers 3`。需要指定工作目录内的官方归档、数据、三个无凭据配置和frozen.json；先用相同隔离参数准备数据、核验，再运行矩阵。原始结果和证据保存在 `/srv/ccpocket/workspace/tmp/2026-10-31/quant-strategy-study/`，不提交原始大行情或临时依赖到Git。

前端在用户更新后的回测布局上补实验、周期、投入和跨周期表，原24项报告保留。网页只读取已完成研究；选择某行不会改变模拟机器人。历史累计收益、CAGR和实时模拟收益有不同口径，不可混用；最大回撤也不保证未来上限。

## 复现输入与证据

`evidence/` 保存无凭据的三份固定仓位配置、两个币种的公共市场精度快照、冻结记录、官方归档清单/数据缺口审计，以及因果和记账检查。原始协议与工程修正前的冻结记录单独保留；原始CSV行情、下载原文、ZIP和运行日志留在上述工作目录，避免向Git重复提交大文件。

1. 用 `python3 research/strategy-study/download_data.py --work <工作目录>` 下载并逐包校验236份新增官方5m/15m归档。
2. 从首轮已校验工作目录复制 `data/BTC_USDT-{1h,4h}.feather`、`data/ETH_USDT-{1h,4h}.feather`；原始1h归档处理见首轮 `prepare_data.py`。复制本目录 `evidence/markets.json`、三份 `config-s*.json` 和 `frozen.json` 至工作目录。
3. 使用 `run_matrix.docker_base()` 的固定镜像、断网和只读挂载参数执行 `/src/prepare_data.py`，生成5m/15m数据。研究工作目录组997可读写，源码组997只读。原始冻结记录用于复核，不重新优化规则。
4. **正式结果必须先准备期末边界。** 运行 `python3 research/strategy-study/prepare_terminal.py --work <工作目录>`，再以相同隔离参数执行 `/src/append_terminal.py`。它校验6份官方日度归档，在`boundary/data/`各追加一根2026-10-01 00:00的截止K线并生成输入SHA冻结；原行逐值一致。保留旧`data/`为同目录时间戳备份，再将`boundary/data/`复制为正式`data/`，不能覆盖后丢失原输入。`boundary/terminal-freeze.json`、下载清单及数据审计须保留。
5. 对正式数据执行 `/src/check_causality.py`，然后运行 `python3 research/strategy-study/run_matrix.py --work <工作目录> --workers 3`，以及 `run_lookahead.py --work <工作目录>`。不要在内存不足的日本节点跑整套研究；矩阵和偏差检查合计最多4任务，单次资源限额见协议。切勿用缺少终端K线的数据复现正式发布结果。
6. 全部54组、210次前缀检查和21个框架抽查变体通过后，用同样隔离参数执行 `/src/export_reports.py`。它拒绝未完成矩阵或未通过检查的结果。输出位于工作目录 `published/study/`；版本目录由规则源码、数据审计、原始结果和导出代码的组合哈希组成。


新机器复现时，审计生成时间与Feather序列化版本可能改变审计文件哈希及发布批次ID；用逐包归档SHA、逐笔记录、钱包和数值结果比较，不把新时间戳或路径误当收益变化。`frozen.json`对应本次确切源码版本；修改了规则或配置，应另开研究批次并在产生结果前冻结，不能修改旧证据覆盖本次记录。

本轮也新增独立1h模拟账户用于冻结后的前向观察，原4h模拟保持原状。两个账户各自1000USDT虚拟资金；顶部切换不改变机器人运行。历史筛选规则与实际选择原因见最终 `RESULTS.md`，回测参数、实际模拟费率/撮合约定及启动日要分别核对。

用户追加授权后，15m单笔250/450的12组任务交由happykai-main的4个隔离研究容器执行，本机继续其余任务与偏差检查；逐文件校验、无重复交接及生产服务保护见[DISTRIBUTED.md](DISTRIBUTED.md)。这是计算资源分配调整，不修改实验规则。

导出阶段的性能分析显示重复月度日期格式化占主要耗时。仅对相同均匀估值时间轴缓存日期索引/月标签，未更改回测或记账公式；三种周期×三段实际区间的新旧曲线、回撤、月度与暴露完全一致，见`evidence/export-cache-check.json`。旧导出源码及中止的部分产物在研究工作目录留存，正式发布批次身份包含新导出器SHA。

本轮实际执行顺序为原378项完成后发现异常，再对所有2026组合统一修正126项；正式比较仍为378项，不把补充重跑当新策略。原21变体框架检查保留，追加边界后另跑210次前缀检查及126项成交时序审计；两者的验证范围在终端修正文档分别说明。
